# Безопасность и приватность

## Текущее состояние

Приложение хранит недельный шаблон, события, задания и настройки в приватной директории Android. Файлы не шифруются отдельным ключом: применяется sandbox и защита устройства. Учителей/кабинеты можно не включать в JSON. Backup отключён, включая правила cloud backup/device transfer. Экспортированные файлы и события становятся доступны выбранному хранилищу или календарю. Календарь может синхронизировать их через своего провайдера.

В APK нет разрешения INTERNET, WebView, API-клиента, токенов, паролей, рекламы, аналитики и crash-reporting SDK. Открытие официального сайта — внешний браузер, его cookies приложению недоступны. Инструкция ИИ попадает в clipboard только по нажатию; фото приложение никуда не отправляет. Выбранный пользователем ИИ может иметь свои правила хранения данных.

## Модель угроз

| Риск | Защита / ограничение |
| --- | --- |
| Огромный/глубоко вложенный JSON | Расписание 256 КиБ, планировщик 2 МиБ; вложенность 12 перед десериализацией |
| Обман через дубли ключей / поля | Дубли, неизвестные поля, неверные типы и управляющие символы отклоняются |
| Ошибка ИИ | Инструкция не допускает догадки; валидатор + полный предпросмотр; ЗС — урок |
| Потеря старого расписания | Проверка до записи, подтверждение замены, AtomicFile |
| Утечка через лог/backup | Содержимое JSON не логируется, backup отключён |
| Фишинг при входе | Фиксированный HTTPS адрес официального сайта, браузер с видимым доменом |
| Компрометация устройства | Sandbox не защищает от root, вредоносной accessibility-службы и разблокированного устройства |
| Передача фото ИИ | Только действие пользователя; совет закрыть персональные данные |
| Подмена зависимости | Закреплённые версии и wrapper; dependency verification и аудит перед публичным релизом |

SHA-256 дистрибутива Gradle закреплён в wrapper properties; контрольная сумма wrapper JAR сверяется с [официальным списком Gradle](https://gradle.org/release-checksums/).

## Требования будущей интеграции

1. Не собирать пароль mos.ru. Предпочитать поддерживаемый провайдером браузерный OAuth Code + PKCE; подтверждать state/callback и profile API. Нельзя утверждать наличие такого доступа, пока оно не установлено.
2. HTTPS, проверка сертификатов, ограниченные hosts для API. Авторизация не следует за redirect на сторонний host. Никаких `SslErrorHandler.proceed`, доверия всем сертификатам или записи всего трафика.
3. Android Keystore + AES-GCM (новый случайный IV на запись), iOS Keychain. Access token в памяти, refresh token — минимально необходимое время в защищённом хранилище. Маскирование не заменяет запрет логирования секретов.
4. Токены не передаются разработчику, в AI, clipboard, analytics, URL query, screenshot, bug report или экспорт. Не хранить собственный сервер с чужими сессиями.
5. Кеш ДЗ/оценок шифровать, привязывать к аккаунту/ребёнку. Новый аккаунт не видит старый кеш. Минимизировать сведения о ребёнке.
6. Logout сначала отменяет запросы/refresh/WorkManager, очищает защищённое хранилище и кеш. Если провайдер поддерживает revoke, выполнить отзыв с ограниченным тайм-аутом; ошибка сети не должна сохранять локальную сессию. Браузерный аккаунт mos.ru может остаться авторизованным — объяснить это пользователю.
7. До выпуска авторизации проверить callback replay, state mismatch, редиректы, изменение API, переключение ребёнка, 401/403, потерю ключа и logout во время sync. Без подтверждённого API интеграция остаётся отключённой.

## Сообщение об уязвимости

Не публикуй реальные токены, пароли, фото детей, школьные идентификаторы или HAR с cookies. В публичной issue допустимы только обезличенные шаги. Приватный канал security reporting пока не настроен; не отправляй секреты через Issues.
